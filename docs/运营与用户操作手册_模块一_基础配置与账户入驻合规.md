## 1. 广告主（Advertiser）账户开设与资质管理

### 1.1 业务场景与风控心智

广告主是平台的**「金主预算源」**。开设账户时，必须严格执行以下风控动作：

| 风控动作 | 目的 | 系统实现 |
|---------|------|---------|
| Anti-Fraud Gate（防跑飞审核） | 防止广告主恶意超量或虚假流量 | `Filters & Caps` 分组中的 `Daily Conversion Caps`、`Reject Cap Must` 字段 |
| 信用账期配置 | 控制平台垫资风险 | `Contract` 分组中的 `Payment Terms` 字段 |
| 预算上限（Cap）配置 | 防止广告主跑飞丢款 | `Filters & Caps` 分组中的 `Daily Conversion Caps` 字段 |
| 合同存证 | 法律追溯依据 | `Contract` 分组中的 `Contract ID`、`Contract Valid To` 字段 |

> ⚠️ **风控红线**：新建广告主时，**必须**填写 `Daily Conversion Caps`（日转化上限）和 `Payment Terms`（账期），否则视为建户不规范，风控运营有权驳回。

---

### 1.2 系统实操步骤

#### 步骤 1：进入模块

1. 登录系统后，鼠标点击**左侧主导航栏**的 **「Workplace」** 菜单
2. 在展开的子菜单中，点击 **「Partner Hub」**
3. 默认进入 **「Advertiser List」** 选项卡（第一个 Tab）

> 💡 **快捷操作**：任何时候按 `Ctrl+K`（Windows）或 `Cmd+K`（Mac）唤起全局命令面板，输入「Advertiser」即可快速跳转。

---

#### 步骤 2：激活创建

在 **Advertiser List** 页面右上角，点击 **「+ New Advertiser」** 按钮：

- 系统右侧滑出 **创建抽屉（Drawer）**，宽度 680px
- 抽屉左侧有**快速导航栏**（7 个分组模块，点击可快速跳转）

---

#### 步骤 3：填写基础表单

创建抽屉分为 **7 个分组模块**，按业务顺序填写：

---

##### 🔴 Required Fields（必填项）

| 字段名 | 系统字段名 | 说明 | 填写规范 |
|--------|------------|------|-----------|
| Advertiser Name | `name` | 广告主公司名称或品牌名 | 必填，建议与合同主体一致 |
| BD（商务负责人） | `businessDev` | 负责该广告主的 BD | 必填，从用户列表单选 |
| AM（账户经理） | `advertiserManager` | 负责该广告主的 AM | 必填，从用户列表单选 |

> ⚠️ 若 `BD` 或 `AM` 未填写，点击 Submit 时会弹出提示「请填写必填项」，无法提交。

---

##### 📋 Basic Info（基础信息）

| 字段名 | 系统字段名 | 说明 | 填写规范 |
|--------|------------|------|-----------|
| Status | `status` | 账户状态 | 默认 `Active`；若资质未审核完，可选 `Pending` |
| Advertiser Name（英文） | `advertiserName` | 广告主英文名 | 用于 Postback 传递，建议与 API 文档一致 |
| Email | `email` | 联系邮箱 | 接收系统通知 |
| Notification Email | `notificationEmail` | 通知邮箱 | 若与 Email 不同，可单独填写 |

---

##### ⚙️ Settings（高级设置）

| 字段名 | 系统字段名 | 说明 | 填写规范 |
|--------|------------|------|-----------|
| API | `api` | 广告主提供的 API 地址 | 用于拉取广告主侧转化数据（可选） |
| Postback URL | `postbackUrl` | 转化回传地址 | 平台发生转化时，向该 URL 发送 Postback 请求 |
| Auto Test | `autoTest` | 自动测试开关 | 开启后，系统会自动发送测试 Postback |
| Is More Tracking | `isMoreTracking` | 多转化追踪开关 | 允许同一 Click ID 多次转化（适用于订阅类业务） |
| Short Click ID | `shortClickid` | 短 Click ID 模式 | 开启后，Click ID 使用短格式（部分广告主要求） |

---

##### 🔍 Filters & Caps（过滤与限额）

| 字段名 | 系统字段名 | 说明 | 填写规范 |
|--------|------------|------|-----------|
| Daily Conversion Caps | `dailyConversionCaps` | 日转化上限 | **风控必填**，建议设置为预估日转化的 120% |
| Daily Total Adv Click Caps | `dailyTotalAdvClickCaps` | 日点击上限 | 可选，防止流量异常突增 |
| Reject Cap Must | `rejectCapMust` | 超 Cap 后拒绝开关 | 开启后，超过 Cap 的转化会被拒绝，不会计入账单 |
| Margin | `margin` | 利润率 | 设置该广告主的默认利润率（百分比） |
| Block Channel | `blockChannel` | 屏蔽渠道 | 填写需要屏蔽的 Channel 名称（逗号分隔） |
| White Channels | `whiteChannels` | 白名单渠道 | 仅允许白名单内的 Channel 投放（与 Block Channel 互斥） |
| IP Whitelist | `ipWhitelist` | IP 白名单 | 限制仅允许指定 IP 段的 Postback 请求 |
| Geo Filter | `geoFilter` | 国家过滤 | 多选，限制仅允许指定国家的流量 |
| Package Block | `packageBlock` | 包名屏蔽 | 填写需要屏蔽的 Package Name（逗号分隔） |
| Campaign ID Filter | `campaignIdFilter` | Campaign ID 过滤 | 限制仅允许指定 Campaign ID 的流量 |
| Weight Min Control | `wegetMin` | 最小权重控制 | 流量分配最小权重（可选） |
| Weight Max Control | `wegetMax` | 最大权重控制 | 流量分配最大权重（可选） |

---

##### 📄 Contract（合同信息）

| 字段名 | 系统字段名 | 说明 | 填写规范 |
|--------|------------|------|-----------|
| Payment Type | `paymentType` | 发票类型 | `Invoice needed`（需要发票）/ `Invoice free`（不需要发票） |
| Payment Terms | `paymentTerms` | 账期 | `Net 15`（15 天账期）/ `Net 30`（30 天账期）|
| Contract ID | `contractId` | 合同编号 | 填写双方签署的合同编号，用于财务对账 |
| Contract Valid To | `contractValidTo` | 合同有效期 | 选择合同截止日期，到期前系统会自动提醒续签 |

> ⚠️ **财务风控**：`Payment Terms` 必须与商务谈判结果一致，填写后不可随意修改。如需修改，需联系财务运营在数据库中直接调整。

---

##### 🏦 Bank Info（银行信息）

| 字段名 | 系统字段名 | 说明 | 填写规范 |
|--------|------------|------|-----------|
| Beneficial Name | `beneficialName` | 收款人姓名 | 与银行账户持有者一致 |
| Bank Name | `bankName` | 银行名称 | 填写银行英文名称 |
| SWIFT Code | `swiftCode` | SWIFT 代码 | 用于国际汇款 |
| Address | `address` | 地址 | 收款人地址 |

---

##### 📝 Memo（备注）

| 字段名 | 系统字段名 | 说明 |
|--------|------------|------|
| Memo | `memo` | 自由文本，记录该广告主的特殊说明（如：特殊结算方式、VIP 标识等） |

---

#### 步骤 4：保存生效

1. 检查表单无误后，点击抽屉底部的 **「Submit」** 按钮
2. 系统调用 `createAdvertiser` 接口，**秒级完成建户**
3. 提交成功后，按钮右侧出现 **绿色对勾 ✓**，持续 3 秒后恢复
4. 抽屉**不会自动关闭**，方便继续创建下一条记录
5. 若需关闭，点击右上角的 **「×」** 按钮

> 💡 **无感刷新**：提交成功后，Advertiser List 表格会自动刷新，无需手动刷新页面。

---

### 1.3 编辑已有广告主

1. 在 Advertiser List 表格中，找到目标广告主
2. 点击该行右侧的 **「Edit」（铅笔图标）** 按钮
3. 系统打开编辑抽屉（标题显示「Edit Advertiser」）
4. 修改需要变更的字段，点击 **「Submit」** 保存

> ⚠️ **注意**：编辑时，`advId`（广告主系统 ID）不可修改。如需修改，需联系开发团队。

---

### 1.4 常见问题（FAQ）

| 问题 | 解决方案 |
|------|---------|
| 提交时提示「请填写必填项」 | 检查 `Advertiser Name`、`BD`、`AM` 是否已填写 |
| 找不到指定的 BD/AM | 联系管理员在 User Management 中先创建该用户 |
| 广告主状态误设为 Inactive | 在 Advertiser List 中找到该广告主，点击 Edit，将 Status 改回 Active |
| 合同即将到期 | 系统会在 Contract Valid To 前 7 天发送提醒（需配置通知邮箱） |

## 2. 渠道商（Publisher）合规入驻与电子协议存证

### 2.1 业务场景与风控心智

海外流量合规和账务法律风险是平台的**生命线**。下游渠道商入驻时，必须通过 **Click-wrap（勾选同意协议）** 机制进行法律约束。

| 合规动作 | 目的 | 系统实现 |
|---------|------|---------|
| Click-wrap 协议签署 | 法律约束，明确双方权利义务 | `Agreement` 页面（`/agreement`） |
| 存证日志完整性核验 | 应对流量仲裁、法律纠纷 | `Agreement` 后台看板（待开发） |
| 防欺诈过滤激活 | 过滤作弊流量 | `Settings` 分组中的 `Anti-Fraud Settings` |
| 流量策略关联 | 控制渠道流量分配 | `Traffic Policy` 分组（关联 Traffic Policy Center） |

> ⚠️ **合规红线**：渠道商在**首次提现或提量前**，必须完成协议签署，且存证日志必须完整（包含用户 ID、时间戳、IP、条款版本号）。否则，风控运营有权暂停该渠道的结算。

---

### 2.2 系统实操步骤

#### 步骤 1：渠道建户

1. 进入 **Partner Hub** 页面
2. 切换到 **「Publisher List」** 选项卡
3. 点击右上角的 **「+ New Publisher」** 按钮
4. 系统右侧滑出创建抽屉（结构与 Advertiser 类似，但字段略有不同）

---

Publisher 创建抽屉同样分为 7 个分组模块：

---

##### 📋 Basic Info（基础信息）

| 字段名 | 系统字段名 | 说明 |
|--------|------------|------|

| Email | `email` | 联系邮箱 |
| Notification Email | `notificationEmail` | 通知邮箱 |

---

##### ⚙️ API & Postback（API 与回传配置）

| 字段名 | 系统字段名 | 说明 | 操作 |
|--------|------------|------|------|
| Key | `key` | 渠道商的 API Key / Token | 系统自动生成，也可手动输入；右侧有「复制」按钮 |
| Request URL | `requestUrl` | Postback 请求地址 | 平台发生转化时，向该 URL 发送 Postback 请求；右侧有「复制」按钮 |
| Postback URL | `postbackUrl` | 渠道侧 Postback 回传地址 | 部分渠道需要平台接收其回传时使用 |
| Postback Type | `postbackType` | Postback 事件类型 | 下拉选择，如 `Install`、`Purchase` 等 |
| Optimize URL | `optimizeUrl` | 优化回调地址 | 用于实时反馈优化信号（可选）|
| Reject Event URL | `rejectEventUrl` | 拒绝事件地址 | 平台拒绝转化时，向该 URL 通知渠道（可选）|

> 💡 **一键复制**：Token 和 Request URL 字段右侧均有「复制」按钮，点击后自动复制至剪贴板，方便配置到渠道侧。

#### 步骤 3：Click-wrap 协议签署（渠道侧操作）

渠道商首次登录平台时，系统会自动重定向至协议签署页面：

1. 渠道商访问平台登录页，输入账号密码
2. 首次登录成功后，系统自动跳转至 `/agreement` 页面
3. 页面展示《服务条款》和《隐私政策》全文
4. 渠道商必须**强制勾选**「我已阅读并同意服务条款与隐私政策」
5. 勾选后，点击「同意并提交」按钮
6. 系统记录以下存证信息并写入数据库：

| 存证字段 | 说明 |
|---------|------|
| 用户 ID | 渠道商的系统 ID |
| 同意时间戳 | 精确到秒的签署时间 |
| 注册/登录 IP | 渠道商签署时的 IP 地址 |
| 条款版本号 | 当前生效的条款版本（如 `v2.3`）|

> ✅ **不可篡改性**：存证日志一旦生成，不可修改或删除，确保法律证据链的完整性。

---

#### 步骤 4：合规日志导出追溯（运营侧操作）

当需要审查某家渠道的合规资质时：

1. 进入 **Agreement** 页面（`/agreement`）
2. 在搜索框中输入 **Publisher ID** 或 **Publisher Name**
3. 系统展示该渠道的签署记录，包括：
   - 用户 ID
   - 同意时间戳
   - 注册/登录 IP
   - 条款版本号
4. 点击 **「导出」** 按钮，导出为 CSV 格式（包含上述所有字段）

> ⚠️ **待确认**：Agreement 页面的具体实现程度（如导出功能是否已开发）需要实际查看系统界面后补充。
