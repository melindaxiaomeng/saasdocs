## 2. 高性能高密度 UI 设计

### 2.1 技术挑战

AdTech SaaS 平台面临的技术挑战：
1. **千行大表**：需要展示上千行数据，不能卡顿
2. **列分割线拖拽**：需要优雅实现列宽调整，不触发 AntD 原生排序事件
3. **固定总计行**：底部总计行需要跟随列拖拽，Index 一一对应
4. **局部编辑**：避免全表重渲染，采用 Popover Editor 代替常态 Input

### 2.2 列分割线拖拽（Resizable Header）

#### 2.2.1 技术选型

**问题**：如何优雅实现列分割线直接拖拽，而不触发 AntD 原生表头排序事件？

**解决方案**：使用 `react-resizable` 库，自定义 `ResizableHeaderCell` 组件

**核心代码**（`src/pages/Finance.jsx`）：

```jsx
// ── Draggable Header Cell — react-resizable wrap entire th ────────────
const ResizableHeaderCell = ({ onResize, width, ...restProps }) => {
  if (!width) return <th {...restProps} />
  return (
    <Resizable
      width={width}
      height={0}
      handle={
        <span
          className="absolute right-0 top-0 z-10 w-1.5 h-full cursor-col-resize translate-x-1/2 select-none active:bg-blue-500/20 transition-colors"
          onClick={(e) => e.stopPropagation()}  // 关键：阻止事件冒泡
        />
      }
      onResize={onResize}
      draggableOpts={{ enableUserSelectHack: false }}  // 禁用用户选择 hack
    >
      <th {...restProps} className={`${restProps.className || ''} relative`} />
    </Resizable>
  )
}
```

#### 2.2.2 关键技术点

1. **事件隔离**：
   - `onClick={(e) => e.stopPropagation()}`：阻止点击事件冒泡到 AntD 表头
   - 避免触发 AntD 原生的排序事件

2. **拖拽优化**：
   - `draggableOpts={{ enableUserSelectHack: false }}`：禁用 `react-draggable` 的用户选择 hack
   - 避免拖拽时选中文本

3. **视觉反馈**：
   - 拖拽分割线：`cursor-col-resize`
   - 拖拽中：`active:bg-blue-500/20`（蓝色半透明背景）
   - 分割线宽度：`w-1.5`（6px），方便点击

4. **宽度约束**：
   - `Math.max(50, size.width)`：最小宽度 50px，避免列宽过小

#### 2.2.3 集成到 AntD Table

**使用方式**：

```jsx
const handleColResize = (key) => (e, { size }) => {
  setColumnWidths(prev => ({ ...prev, [key]: Math.max(50, size.width) }))
}

const columns = [
  {
    title: (title) => (
      <ResizableHeaderCell
        width={columnWidths['publisher']}
        onResize={handleColResize('publisher')}
      >
        Publisher
      </ResizableHeaderCell>
    ),
    dataIndex: 'publisher',
    key: 'publisher',
    width: columnWidths['publisher'] || 140,
  },
  // ... 其他列
]
```

**效果**：
- 鼠标悬停在列右侧时，光标变为 `col-resize`
- 拖拽分割线时，列宽实时调整
- 不触发 AntD 表头排序事件

### 2.3 底部 Table.Summary 固定总计行

#### 2.3.1 技术挑战

**问题**：底部 Table.Summary 固定总计行的 Index 一一对应与跟随拖拽机制

**解决方案**：使用 AntD Table 的 `Table.Summary` 组件，通过 `index` 属性实现一一对应

**核心代码**（`src/pages/Finance.jsx`）：

```jsx
<Table
  dataSource={confirmedRows}
  columns={columns}
  summary={() => (
    <Table.Summary fixed="bottom">
      <Table.Summary.Row className="bg-gray-50 font-bold">
        <Table.Summary.Cell index={0} colSpan={3}>
          Total ({confirmedRows.length} records)
        </Table.Summary.Cell>
        <Table.Summary.Cell index={1}>
          {totalRevenue.toFixed(2)}
        </Table.Summary.Cell>
        <Table.Summary.Cell index={2}>
          {totalPayout.toFixed(2)}
        </Table.Summary.Cell>
        <Table.Summary.Cell index={3}>
          {totalConv}
        </Table.Summary.Cell>
        <Table.Summary.Cell index={4}></Table.Summary.Cell>
      </Table.Summary.Row>
    </Table.Summary>
  )}
/>
```

#### 2.3.2 关键技术点

1. **Index 一一对应**：
   - `Table.Summary.Cell` 的 `index` 属性对应列的索引
   - 第 0 列：`index={0}`，第 1 列：`index={1}`，以此类推
   - 确保总计行与表头对齐

2. **列合并**：
   - `colSpan={3}`：合并前 3 列（Publisher、Advertiser、Campaign）
   - 用于显示"Total (N records)"文本

3. **固定底部**：
   - `fixed="bottom"`：固定总计行在表格底部
   - 即使表格滚动，总计行始终可见

4. **跟随拖拽**：
   - 当列宽拖拽时，`Table.Summary.Cell` 的 `index` 不变
   - AntD 自动处理列宽变化，总计行自动跟随

#### 2.3.3 动态列场景

**问题**：当列动态显示/隐藏时，如何保持 Index 一一对应？

**解决方案**：动态计算 `index`

```jsx
const getSummaryCells = () => {
  const cells = []
  let index = 0
  
  // Checkbox 列
  if (showCheckbox) {
    cells.push(<Table.Summary.Cell key="_check" index={index} />)
    index++
  }
  
  // 维度列
  if (showPublisher) {
    cells.push(<Table.Summary.Cell key="publisher" index={index}>Total</Table.Summary.Cell>)
    index++
  }
  
  // 数值列
  if (showRevenue) {
    cells.push(<Table.Summary.Cell key="revenue" index={index}>{totalRevenue.toFixed(2)}</Table.Summary.Cell>)
    index++
  }
  
  return cells
}
```

**效果**：
- 无论列如何动态显示/隐藏，`index` 始终一一对应
- 总计行始终正确对齐

### 2.4 局部气泡动态输入框（Popover Editor）

#### 2.4.1 技术挑战

**问题**：如何做到千行大表不卡顿？

**传统方案的问题**：
- 常态 Input：每行每个单元格都是 Input，千行表格有上万个 Input，渲染卡顿
- 全表重渲染：编辑一个单元格，整表重新渲染

**解决方案**：使用 Popover Editor（局部气泡动态输入框）

**核心思路**：
1. 默认状态：单元格显示纯文本（极低渲染成本）
2. 点击单元格：弹出 Popover，内部包含 Input
3. 编辑完成：关闭 Popover，更新数据，只重渲染当前行

#### 2.4.2 实现方式

**方案 1：Finance.jsx 的快速编辑**

```jsx
const [editingCell, setEditingCell] = useState(null)  // { rowId, field }
const [editValue, setEditValue] = useState('')

const columns = [
  {
    title: 'Scrub Rev.',
    dataIndex: 'scrubRevenue',
    render: (value, record) => {
      const isEditing = editingCell?.rowId === record.id && editingCell?.field === 'scrubRevenue'
      
      if (isEditing) {
        return (
          <Input
            value={editValue}
            onChange={(e) => setEditValue(e.target.value)}
            onBlur={saveEdit}
            onPressEnter={saveEdit}
            autoFocus
            className="w-full"
          />
        )
      }
      
      return (
        <span
          onClick={() => {
            setEditingCell({ rowId: record.id, field: 'scrubRevenue' })
            setEditValue(value)
          }}
          className="cursor-pointer hover:bg-blue-50 px-1 py-0.5 rounded"
        >
          {value.toFixed(2)}
        </span>
      )
    },
  },
  // ... 其他列
]
```

**方案 2：UnifiedAccountVault.jsx 的 MaskCell**

```jsx
function MaskCell({ value }) {
  const [visible, setVisible] = useState(false)
  const display = visible ? value : '•'.repeat(Math.min(value?.length || 8, 16))
  
  return (
    <div className="flex items-center gap-1">
      <span className={`font-mono text-[11px] ${visible ? 'text-gray-700' : 'text-gray-400'}`}>
        {display}
      </span>
      <button
        onClick={() => setVisible(v => !v)}
        className="text-gray-400 hover:text-gray-600 transition-colors"
      >
        {visible ? <EyeOff size={11} /> : <Eye size={11} />}
      </button>
    </div>
  )
}
```

#### 2.4.3 性能优化效果

**对比**：

| 方案 | 渲染成本 | 千行表格 |
|------|----------|----------|
| 常态 Input | 高（每个单元格都是 Input） | 卡顿（上万个 Input） |
| Popover Editor | 低（默认纯文本，点击后创建 Input） | 流畅（只渲染当前编辑的 Input） |

**关键优化**：
1. **惰性渲染**：默认状态不创建 Input，点击后才创建
2. **局部更新**：只更新当前编辑的行，不重渲染整表
3. **虚拟滚动**：超过 100 行时启用虚拟滚动（AntD Table 的 `virtual` 属性）

```python
# 伪代码
def get_anomaly_warning(date_range, threshold, advertiser_id=None, publisher_id=None):
    # 1. 查询当月所有 campaign 的 conversion 数据
    campaigns = Campaign.objects.filter(
        date__range=date_range,
        ...
    )
    
    # 2. 计算每个 campaign 的异常率
    for campaign in campaigns:
        pb_conv = campaign.postback_conversions
        scrub_conv = campaign.scrub_conversions
        
        if pb_conv > 0:
            anomaly_rate = abs(scrub_conv - pb_conv) / pb_conv
        else:
            anomaly_rate = 0
            
        # 3. 筛选异常率超过阈值的 campaign
        if anomaly_rate > threshold:
            result.append({
                'campaign_id': campaign.id,
                'campaign_name': campaign.name,
                'anomaly_rate': anomaly_rate,
                ...
            })
    
    # 4. 按异常率降序排序
    result.sort(key=lambda x: x['anomaly_rate'], reverse=True)
    
    return result
```

## 4. 代码心智与底层设计

### 4.1 设计哲学

#### 4.1.1 实用主义

**理念**：不追求完美设计，但求解决实际问题

**示例**：
- Finance.jsx 的 CSV BOM 处理：`rawId.replace(/^\ufeff/, '')`（简单有效）
- 快速编辑功能：点击单元格直接编辑，无需双击或按钮（减少操作步骤）

#### 4.1.2 渐进增强

**理念**：先实现基础功能，再逐步优化

**示例**：
- 最初版本：Finance 表格不支持列宽拖拽
- 优化版本：集成 `react-resizable`，支持列宽拖拽
- 再优化：解决拖拽触发排序问题，优化视觉反馈

#### 4.1.3 用户同理心

**理念**：站在用户角度思考，减少操作步骤

**示例**：
- Upload Statement：拖拽上传 + 点击上传双支持
- 快速编辑：点击即编辑，回车保存，ESC 取消（符合用户习惯）
- 2FA 动态码：点击即复制，倒计时可视化（降低用户认知负担）

### 4.2 代码组织

#### 4.2.1 组件设计原则

1. **单一职责**：每个组件只做一件事
   - `ResizableHeaderCell`：只负责列宽拖拽
   - `UploadPanel`：只负责文件上传
   - `ReasonModal`：只负责显示原因详情

2. **可组合性**：小组件组合成大组件
   - `Finance.jsx` = `UploadPanel` + `ReasonModal` + `StatementModal` + `DateRangePicker` + ...

3. **状态提升**：共享状态提升到最近公共父组件
   - `editingCell` 和 `editValue` 在 `Finance.jsx` 中管理
   - 传递给子组件（通过 props 或 context）

#### 4.2.2 API 封装原则

1. **统一入口**：所有 API 调用通过 `src/api/` 目录
2. **统一错误处理**：`src/utils/request.js` 拦截器统一处理错误
3. **统一响应格式**：后端返回统一格式（成功/失败/错误信息）

**request.js 核心代码**：

```javascript
// 响应拦截器
request.interceptors.response.use(
  (response) => {
    // returnFullResponse: true 时，跳过解包，返回完整响应对象
    if (response.config.returnFullResponse) {
      return response
    }
    
    // 正常情况：解包，返回 data
    return response.data
  },
  (error) => {
    // 统一错误处理
    message.error(`Request failed: ${error.message}`)
    return Promise.reject(error)
  }
)
```

### 4.3 性能优化心智

#### 4.3.1 渲染优化

**原则**：能不渲染就不渲染，能延迟渲染就延迟渲染

**技巧**：
1. **惰性渲染**：`editingCell` 控制当前编辑的单元格，只渲染一个 Input
2. **条件渲染**：`uploadStatus === 'success' &&` 只有上传成功后才渲染预览表格
3. **分页渲染**：`pagedList` 只渲染当前页的数据

#### 4.3.2 计算优化

**原则**：能缓存就缓存，能增量更新就增量更新

**技巧**：
1. **useMemo**：缓存计算结果，依赖项变化时才重新计算
2. **增量更新**：`setData(prev => [...prev, newItem])` 而不是重新加载整个列表

**部署环境**：
- **服务器**：阿里云 ECS
- **IP**：`121.43.101.136`
- **操作系统**：Windows Server 2022
- **Web 服务器**：Nginx 1.26.3
- **部署目录**：`C:\saas_new\`

**部署流程**：
1. 本地构建：`npm run build`
2. 上传 `dist/` 目录到服务器
3. 重启 Nginx：`nginx -s reload`

### 5.2 注意事项

**阿里云部署注意**：
1. **文件嵌套目录问题**：Windows 路径长度限制，避免过深的嵌套
2. **nginx.conf 配置**：`base64` 写入，避免编码问题
3. **静态资源**：确保 `dist/` 目录下的所有文件都上传
